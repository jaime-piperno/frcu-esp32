Connect to Device

The browser can't connect to WiFi on your behalf — first connect your phone/laptop to the ESP32's network (or a shared network) via your device's WiFi settings, then enter the device IP here.

Device Address

Connection address: ws://192.168.4.1:81/

Guide

1. If the ESP32 creates its own Access Point, connect your phone/laptop to that network (e.g. ESP-CNC). The default address is usually 192.168.4.1.
2. If the ESP32 is connected to your home/office router, find its IP address in the router settings or via the Arduino Serial Monitor.
3. Enter the WebSocket port to match the code uploaded to the ESP32 (in most AsyncWebSocket projects, port 81 or 80 is common).
4. If this site is opened over HTTPS, the browser will usually block an insecure ws:// connection. Open this page from a local server or an HTML file, not from an HTTPS domain.

Motion Settings

The default speeds used when sending commands.

Feedrates

A lower speed means more accurate but slower drawing; a higher speed is faster but increases the risk of vibration/skipped steps. If you want higher accuracy, lower both Rapid and Pen.

Pause After Raising/Lowering the Pen

The pen (servo) needs real physical time to fully raise or lower. Without this pause, the next move can start before it's finished, so the pen gets dragged across the paper before it's fully up, drawing an extra line between two unrelated points — exactly the kind of stray diagonal line you'd see, e.g., an eye's shading ending up drawn above the eyebrow instead of inside the eye. If you're seeing this, increase this number (e.g. 300-500).

Device Communication (preventing hangs/Wi-Fi drops)

When G-Code lines are sent one after another too quickly (for example, if the ESP32 acknowledges a line before the actual movement finishes), the ESP32's processor gets busy running the command queue and doesn't give the Wi-Fi task enough time — the result is a hang or a Wi-Fi drop mid-drawing. This number adds a mandatory pause between each line and the next (separate from the device's acknowledgment) so that, regardless of firmware behavior, sending never gets too fast. If you're still having trouble, increase this number (e.g. 50-100).

Drawing Order

Instead of drawing lines in whatever order they were found in the image (which made the pen constantly jump back and forth across the image), nearby lines are drawn one after another so the pen travels less.

G-Code Output File Header

If the G-Code file moves incorrectly without these (e.g. moving relative to the last point instead of using absolute coordinates), keep this checked.
